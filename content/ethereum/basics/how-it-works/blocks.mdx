A **block** is a batch of transactions, along with the hash of the block right before it. Blocks link together to form a [blockchain](./blockchain.mdx).

## Why bundle transactions into blocks?

Thousands of nodes around the world need to hold the same data. If each transaction were recorded the moment it arrived, nodes would receive them in different orders and would never match up. Bundling transactions into blocks, spaced a fixed time apart, gives the whole network enough time to agree. The order of the blocks, and the order of the transactions inside each block, are both clear.

## A slot every 12 seconds

Time on Ethereum is split into **slots** that are 12 seconds long. Every 32 slots make up an **epoch**, which lasts 6.4 minutes.

- In each slot, one validator is chosen at random to be the block **proposer**.
- If the proposer is absent, the slot is empty and there's no block.
- So the time between two blocks is 12 seconds, or a multiple of 12 seconds. With "mining" (proof of work), which Bitcoin still uses and Ethereum used until 2022, the time between blocks is random. With proof of stake, it's fixed.

## How a block is made

<BlockAnatomy />

1. **Gather transactions.** Transactions are picked from the **mempool** (the queue of waiting transactions) and placed into a block. Today most blocks are built by professional **block builders**, who then sell them to proposers through MEV-Boost. The animation on the [home page](/ethereum) shows this process.
2. **Run the transactions.** The transactions are run in order, producing Ethereum's new state: new balances, new contract data.
3. **Write the block header.** The block header records the key information, as in the table below.
4. **Publish and check.** Other nodes rerun every transaction in the block for themselves. If the result matches the state root recorded in the block, the block is valid. Validators vote for the block, and it's added to the chain.

## When can a block no longer be reversed?

Once a block has just been added to the chain, your transaction has "succeeded", but in theory that block could still be replaced, though it's very rare. A block is only certain once it reaches **finality**.

<FinalityScene />

1. **Checkpoint.** The first block of each epoch is a **checkpoint**. If the first slot of the epoch is empty, the closest block before it serves as the checkpoint.
2. **Voting.** In each epoch, every active validator casts one vote for that epoch's checkpoint. Votes are weighted by the amount of staked ETH.
3. **Justified.** When the votes for a checkpoint reach 2/3 of all staked ETH, that checkpoint is **justified**.
4. **Finality.** When the next checkpoint is also justified, the earlier checkpoint reaches finality, and so does every block before it.

So from the moment it's included in a block, your transaction waits 2 to 3 epochs, about 13 to 19 minutes, depending on whether it lands near the start or the end of an epoch. There's no 2/3 rule for each individual block: votes are counted per epoch.

To reverse a block that has reached finality, at least 1/3 of all staked ETH would have to sign for two conflicting branches. That gets detected and slashed, so reversing a block costs at least 1/3 of the ETH protecting the network. If validators holding more than 1/3 of the stake stop working, the chain keeps producing blocks but temporarily doesn't reach finality, until 2/3 is back. See [Consensus](./consensus.mdx#proof-of-stake).

## What's inside a block?

| Part | Meaning |
|---|---|
| Slot | Which slot the block belongs to |
| Proposer | The validator chosen for this slot |
| Parent block hash | The thread that ties it to the previous block |
| State root | A hash that sums up all of Ethereum's balances and data after this block |
| Timestamp | When the block was created |
| Gas limit, gas used, base fee | How big the block is and where fees are at |
| Transactions | The list of transactions, in the exact order they were run |
| Attestations | Validators' votes for earlier blocks |

An Ethereum block usually holds anywhere from a few dozen to a few hundred transactions.

## How big is a block?

Block size isn't measured in bytes but in **gas**, the unit that measures computation. Each block has a **gas limit**, and a target equal to half the limit.

- If a block uses more gas than the target, the next block's base fee goes up, by at most 12.5%. If it uses less, the fee goes down. See [Gas fees](../getting-started/gas-fees.mdx).
- Validators can raise or lower the gas limit little by little with each block. According to ethereum.org, the limit was 60 million gas at the end of 2025. This number is being raised gradually, so check live data if you need the exact figure.

Why not make blocks really big so they're cheap? The bigger the blocks, the more powerful the computer needed to run a node. When only very powerful machines can keep up, fewer people run their own nodes, and the network gradually ends up in the hands of a few. [Layer 2](./layer-2.mdx) is how Ethereum scales without having to make that trade-off.

## Summary

- A block is a batch of transactions plus the hash of its parent block.
- Each 12-second slot has at most one block, proposed by a randomly chosen validator.
- Every node reruns the transactions itself to check a block before adding it to the chain.
- After 2 to 3 epochs (about 13 to 19 minutes), a block reaches finality and can't be reversed without losing at least 1/3 of all staked ETH.
- Block size is capped with gas, so ordinary people can still run a node.
