When you make a transfer at a bank, the bank confirms you own the account with your password and a one-time code (OTP). Ethereum has no one in the middle to confirm anything. Instead, every transaction carries a **digital signature**.

A digital signature lets anyone check two things:

1. The transaction was signed by the person who holds the private key.
2. The contents of the transaction haven't been changed since it was signed.

Without signatures, anyone could broadcast an order like "send 5 ETH from Alice's account to mine", and no one could tell whether the order really came from Alice.

## What's in a transaction?

A **transaction** is a signed instruction sent from an account. Its main parts:

| Part | Meaning |
|---|---|
| From | The sending address, which is the one that signs the transaction |
| To | The receiving address: a person, or a smart contract |
| Value | The amount of ETH being sent |
| Data | An instruction for a smart contract, if any. Left empty for a plain ETH transfer |
| Nonce | The account's transaction counter: 0, 1, 2… |
| Gas limit, max fee, priority fee | How much you're willing to pay in fees. See [Gas fees](../getting-started/gas-fees.mdx) |
| Signature | Created by the wallet with your private key, from all of the contents above |

## Signing and checking

<SignatureScene />

Your wallet signs the transaction right on your device. The private key never leaves the wallet. All that gets sent to the network is the transaction's contents plus the signature.

Every node that receives the transaction checks it for itself. From the signature and the contents, the node works out the public key, and from that the signer's address. If that address matches the sender, the signature is valid. The node can do this without knowing your private key.

If someone changes the contents along the way, even by a single digit, the check produces a different address. The transaction is rejected. To get a valid signature for the new contents, they would need your private key.

## Nonce: each transaction runs only once

Every account has a counter called the **nonce**. The first transaction has nonce 0, the next has nonce 1, and so on. For each account, each nonce can be used only once.

That's why a scammer can't take a transaction you've already signed and send it again to pull out more money. That kind of attack is called a **replay attack**.

The nonce also explains a common situation: if one transaction gets stuck because its fee was too low, your later transactions have to wait for it. Wallets usually let you speed up or cancel a stuck transaction by sending a new transaction with the same nonce.

## Read carefully whatever you sign

Signatures aren't only for sending ETH. You also sign when you swap tokens, log in to an app, or allow a smart contract to use your tokens. A signature counts just like a real one: once you've signed, you can't take it back.

The problem is that many signature requests show only a string of hard-to-read characters. Signing without understanding what you're signing is called **blind signing**, and it's how many people lose money. Newer wallets are moving to **clear signing**, which spells out what the transaction is meant to do in plain words, for example "Swap 1,000 USDC for at least 0.25 WETH".

<Callout type="warn" title="Warning">
Don't sign anything you don't understand. A single permission signature (approve or permit) given to an unfamiliar site can let a scammer drain all of that token from your wallet without asking again. See [Staying safe](../getting-started/staying-safe.mdx).
</Callout>

## Summary

- A digital signature proves a transaction was signed by the key holder and hasn't been changed.
- Anyone can check a signature without knowing the private key.
- The nonce numbers each transaction, so a signed transaction can't be sent again to run a second time.
- Only sign when you clearly understand what you're signing.
