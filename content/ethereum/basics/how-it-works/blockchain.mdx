Imagine a ledger that records every transaction, copied onto thousands of computers around the world. Anyone can read it. To add to it, you have to follow the shared rules. And changing an old page is all but impossible, because every other copy would immediately see that something is wrong.

That's the idea behind a **blockchain**: a public database that is updated and shared among many computers in a network.

## Blocks and chains

Data isn't recorded one line at a time. It's gathered into groups called **blocks**. An Ethereum block usually holds anywhere from a few dozen to a few hundred transactions. A transaction only counts as successful once it's inside a block.

Blocks are linked into a chain by **hashes**:

- A hash is like a fingerprint for data. The same data always gives the same hash.
- Change even a single character and the hash changes completely.
- There's no way to work backward from a hash to the original data.

Each block records the hash of the block right before it, called its **parent block**. That's the thread tying the blocks together, from the newest block all the way back to the very first one in 2015.

## Why can't the past be secretly changed?

Suppose someone wants to change a transaction in an old block, for example the amount they sent:

1. The block's contents change, so that block's hash changes too.
2. The next block still records the old hash, so the two no longer match. The chain is broken.
3. To reconnect it, that person would have to redo every block after it, then convince the whole network to accept their version.

That last step is impossible on Ethereum. Every node checks each block itself and only follows the chain with the most votes, counted by the amount of ETH staked. A secretly altered version gets ignored by the other nodes.

## Who keeps the blockchain?

The computers that keep the blockchain are called [**nodes**](./nodes.mdx). Each node keeps a full copy and checks every new block itself, without taking anyone's word for it. Thousands of nodes are run by individuals, companies and organizations in many countries, so the network keeps running even if some of them shut down.

## Who gets to add new blocks?

The nodes have to agree with each other on every new block. The way they reach agreement is called a **consensus mechanism** (see [Consensus](./consensus.mdx)). Ethereum uses **proof of stake**:

- [**Validators**](./validators.mdx) stake ETH as collateral and run validator software.
- Every 12 seconds, one validator is chosen at random to propose a new block. The other validators check that block and vote for it.
- Doing the job right earns rewards. Cheating or being absent brings penalties, the harshest being the loss of part of the stake.

After about 13 to 19 minutes, once two consecutive checkpoints have both received votes from 2/3 of all staked ETH, the block reaches **finality**. To reverse that block, an attacker would have to accept losing at least 1/3 of all staked ETH. The animation on the [home page](/ethereum) shows this whole process.

<Callout type="info" title="Note">
There has been no "mining" on Ethereum since 2022. Proof of work was replaced by proof of stake in the event known as The Merge.
</Callout>

## Ethereum: a blockchain with a computer inside

Bitcoin's blockchain mostly records who sent how much to whom. Ethereum records one more thing: the **state** of a shared computer called the **EVM** (Ethereum Virtual Machine). The state includes the balance of every account and the data of every smart contract.

Each transaction is a request for computation. When a new block is added, every node runs the transactions in that block and arrives at the same new state. That's why applications on Ethereum run the same way everywhere.

## Summary

- A blockchain is a public ledger, copied onto thousands of nodes.
- Each block records the hash of its parent block. Changing an old block breaks the chain and gets caught by the other nodes.
- Validators stake ETH so they can propose and vote on new blocks. Cheaters lose their stake.
