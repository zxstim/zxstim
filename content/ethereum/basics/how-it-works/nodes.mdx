The Ethereum network doesn't run on any one company's servers. It's thousands of computers connected to each other, and each one is called a **node**. Every node keeps a copy of the [blockchain](./blockchain.mdx) and checks every new block itself, without taking anyone's word for it.

## What makes up a node?

A node is two pieces of software running together on one machine:

- **Execution client**: receives transactions, runs them in the EVM and keeps Ethereum's state, meaning the balances and data of every account.
- **Consensus client**: handles [consensus](./consensus.mdx), following blocks and votes to know which chain is the right one.

Anyone who wants to be a [validator](./validators.mdx) also runs validator software and stakes 32 ETH. Just running a node doesn't need any ETH at all.

Each layer has several clients, written by independent teams in different programming languages, so that a bug in one client can't break the whole network:

| Layer | Some of the clients |
|---|---|
| Execution | Geth, Nethermind, Besu, Erigon, Reth, ethrex |
| Consensus | Lighthouse, Prysm, Teku, Nimbus, Lodestar, Grandine |

## Types of nodes

- **Full node**: checks every block and keeps the recent state. This is the most common type.
- **Archive node**: keeps every past state and takes up terabytes of space. Block explorers and analytics services use this type.
- **Light client**: downloads only the headers of blocks. It's very lightweight and can run on a phone. According to ethereum.org, no light client software is yet considered ready for real-world use.

## Why run a node yourself?

- **Verify for yourself.** Your node checks every block and every balance on its own. You don't have to trust anyone, in keeping with the spirit of "don't trust, verify."
- **Privacy.** When your wallet asks a public node for data, that node sees your IP address and your wallet addresses. Ask your own node and nobody sees them.
- **Censorship resistance.** A provider can refuse transactions from certain addresses or certain countries. Your own node won't.
- **Help keep the network decentralized.** The more people run their own nodes, the harder the network is to control. It's the nodes that force validators to follow the rules.

## Whose node is your wallet using?

Most wallets don't run a node of their own. They query nodes run by service providers (RPC providers) such as Infura or Alchemy. This is convenient, but you have to trust the provider to answer truthfully and not misuse your data. Providers don't hold your private key and can't take your money.

Many wallets let you switch to a different RPC address, including one pointing to your own node.

## What kind of machine do you need?

ethereum.org's pages give slightly different requirements, because Ethereum's data keeps growing over time:

| | Minimum | Recommended (EIP-7870) |
|---|---|---|
| CPU | 2 or more cores | 4 or more cores |
| RAM | 16 GB | 32 GB |
| Storage | 2 TB NVMe SSD | 4 TB NVMe SSD |
| Network | 25 Mbit/s or more | 50 Mbit/s download, 15 Mbit/s upload |

The drive is usually the most important part. Use an internet plan without a data cap, because a node exchanges data constantly. There are ready-made plug-and-play machines (such as DAppNode) and tools that make setup easier (such as eth-docker, Stereum and Sedge).

## Summary

- A node is a computer running two pieces of software: an execution client and a consensus client.
- A node checks every block itself, so you don't have to trust anyone. Running a node doesn't need any ETH.
- Most wallets use a provider's node. Running your own node gives you more privacy and resists censorship.
