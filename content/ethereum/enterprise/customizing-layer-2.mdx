A dedicated Layer 2 is like a building on a foundation that is Ethereum. You design the building yourself: who gets in, what they pay with, where the paperwork is kept. But the more you do yourself, the more users have to trust you rather than the foundation.

## What you can customize, and what it costs

- **Your own fee token** (custom gas token). Users pay fees in a token you choose instead of ETH. In exchange, they need to hold that token before they can use the network.
- **Block time.** Faster blocks, near-instant confirmation. A fast confirmation is the sequencer's promise; finality still comes from Ethereum, once the data and proofs are recorded there.
- **Who may take part** (allow-list): who may send transactions, who may deploy contracts. The operator can refuse, so the network is less neutral.
- **Where data is stored.**
  - Posted to Ethereum (rollup): anyone can reconstruct the state. This is the safest option.
  - Kept elsewhere (validium, data committee): cheaper and can be kept private, but if the data isn't published, users' funds can get stuck.
- **Privacy.** Keep transaction data hidden from outsiders, send only proofs to Ethereum, and open it up to auditors or regulators when needed.
- **Who may upgrade.** Whoever holds the upgrade keys can change the network's rules. This is the main factor that decides a rollup's [Stage](./layer-2-for-enterprise.mdx).

## Four popular stacks

Based on each project's official documentation, read on November 8 and 9, 2026.

### OP Stack (Optimism)

- **Custom fee token:** yes, using an existing token or a newly created one.
- **Block time:** set in whole seconds, usually 1 or 2 seconds.
- **Sequencer:** one sequencer per network, with a failover mechanism.
- **Allow-list:** the documentation doesn't describe a built-in feature.
- **Data:** posted to Ethereum by default. The mode that keeps data elsewhere (Alt-DA) is still experimental. According to the OP Stack's own documentation, this mode currently relies entirely on trusting the operator.
- **Upgrades:** the owner of the governance contract on Ethereum. Networks under Optimism governance use a multisig wallet of the Optimism Foundation together with a security council.
- **Examples:** Base, Ink, Unichain, World Chain, Soneium.

### Arbitrum (Orbit chains)

- **Custom fee token:** yes, with a standard ERC-20 token.
- **Block time:** 250 milliseconds by default, can go down to 100 milliseconds.
- **Allow-list:** yes, at the sequencer and at the inbox that receives transactions from Ethereum. People not on the list can't push their own transactions through Ethereum either.
- **Compliance filtering:** starting with ArbOS 61 (2026), the operator can turn on filtering against a list of restricted addresses. This feature is off by default. See [Compliance](./compliance.mdx).
- **Data:**
  - Rollup mode posts data to Ethereum.
  - AnyTrust mode hands data to a committee you choose. The Arbitrum documentation notes that the chain owner is the real root of trust, since it can replace the whole committee in a single transaction.
- **Upgrades:** the chain owner.
- **Example:** Robinhood Chain.

### ZK Stack and Prividium (ZKsync)

- **Custom fee token:** yes. Once chosen, it can't be changed back.
- **Sequencer:** centralized or decentralized. There is always a priority queue through Ethereum as an escape hatch.
- **Allow-list:** there is a transaction filter. The documentation warns that users added to a block list later on may have their funds locked.
- **Data:** rollup mode is recommended. In validium mode, funds can't be stolen, but they can be frozen if the data isn't published.
- **Prividium:** a validium-style private chain.
  - Data lives in the operator's database; Ethereum receives only state roots and proofs.
  - Only authorized people can deploy contracts. Each function has its own permissions, and users sign in with their company accounts.
  - Auditors and regulators get selective visibility.
  - Production use requires a commercial license.
- **Upgrades:** protocol upgrades go through the shared governance of the ZKsync ecosystem; the operator chooses when to apply them.

### Polygon CDK

- **Foundation:** currently built on the OP Stack, or on Hyperledger Besu.
- **Modes:**
  - "Sovereign" is the default. Its proofs only show that the network can't withdraw more than was deposited, not that every transaction is correct.
  - Validium is available.
  - Rollup with zero-knowledge proofs is in development.
- **Privacy:** data lives on servers run by the organization itself. According to the Polygon documentation, if that server loses its data, proofs can no longer be generated.
- **Allow-list:** policies for the sequencer, such as accepting only KYC'd transactions, plus company-account sign-in for RPC. Some parts you have to build yourself.

## Checklist before you choose

1. **Is the data posted to Ethereum?** If not, who holds it, and what happens if they stop publishing it?
2. **Is there an escape hatch?** Can users withdraw their assets to Ethereum when the operator stops or refuses, and how long does it take?
3. **Who holds the upgrade keys,** and how many days do users have to withdraw before an upgrade?
4. **What does the allow-list apply to:** only regular transactions, or also the path for pushing transactions through Ethereum yourself?
5. **What Stage has the network reached** on ETHBEAT, and is there a plan to move up?
6. **If the network shuts down,** how do users withdraw their assets?

## Summary

- A dedicated Layer 2 can customize its fee token, block speed, participation rights, data storage, privacy and upgrade rights.
- Each customization shifts some trust from Ethereum to the operator. Keeping data off Ethereum is the biggest trade-off.
- Ask six questions before choosing: data, escape hatch, upgrade keys, allow-list, Stage, and the plan for shutting down.
